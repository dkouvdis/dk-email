# New-mail notifications

This guide covers how dk-email tells you about new mail while it runs in a
terminal, and how to get desktop notifications working in yours.

- [What triggers an alert](#what-triggers-an-alert)

- [Your terminal decides what an alert looks like](#your-terminal-decides-what-an-alert-looks-like)

## What triggers an alert

dk-email checks for new mail on every refresh: each `refresh_interval`
(default `120s`) and when you press `ctrl+r`.

New mail means messages that arrived in an account's INBOX since the last
refresh. Mail that dk-email itself moves into the INBOX doesn't count, the
first refresh after connecting never alerts, and other folders are never
announced.

There is one alert per refresh, covering all accounts:

```
dk-email: 3 new in Work, 1 in Personal
```

The alert is a count only. It never shows a sender or a subject, so nothing
private appears on a locked screen or in a shared notification centre.

There are three channels:

| Channel | What it does |
|---|---|
| Bell | Sends a bell character (BEL) to the terminal. |
| Desktop | Sends an OSC 9 escape sequence with the alert text. Terminals that support it turn it into a system notification. |
| Title | Sets the window title to `dk-email (N)`, where N is the unread count across all INBOXes. At 0 it reads `dk-email`. |

Bell and desktop alerts are skipped while the dk-email window has focus. Mail
found while you were looking at the window isn't announced later. The title
always updates.

dk-email learns about focus from the terminal (focus reporting). Any key
press, click, scroll or paste also counts as being at the window, so
terminals that don't report focus still go quiet once you use dk-email.

## Settings

```toml
[notify]
bell    = true
desktop = true
title   = true
```

All keys are optional and on by default. Unknown keys are rejected, like the
rest of the config.

- `bell = false` stops the bell.
- `desktop = false` stops the OSC 9 notification.
- `title = false` leaves the terminal title alone.

When dk-email exits, the title is cleared. It isn't restored to what it was
before.

## Your terminal decides what an alert looks like

dk-email only sends a bell and an OSC 9 sequence. Whether that becomes a
sound, a flash, a dock badge or a banner is up to your terminal and macOS.

On macOS, open System Settings, then Notifications, then your terminal app.
Allow notifications for it and choose Banners, Alerts or None.

## Terminal setup

**Ghostty.** Desktop notifications from OSC 9 are controlled by the
`desktop-notifications` setting, which is on by default. What the bell does
is controlled by `bell-features`.

**iTerm2.** Open Settings, then Profiles, then Terminal, then Notifications.
The bell options are there. Under "Filter Alerts…", allow alerts generated by
escape sequences, or desktop alerts won't appear.

**Terminal.app.** It doesn't support OSC 9, so only the bell and the title
work.

**tmux.** Two settings matter:

```
set -g allow-passthrough on   # desktop alerts (tmux 3.3 or later)
set -g focus-events on        # lets dk-email know when the window has focus
```

dk-email wraps the OSC 9 sequence for tmux when `$TMUX` is set, but tmux
drops it unless `allow-passthrough` is on. The bell marks the tmux window
(`monitor-bell`, on by default).

**SSH.** The bell and OSC 9 travel over SSH to your local terminal, so
desktop alerts appear on the machine you're sitting at.

## Troubleshooting

**No banner.** Check, in this order:

1. The `[notify]` section doesn't have `desktop = false`.
2. Your terminal supports OSC 9 and has it enabled (see above). Terminal.app
   doesn't.
3. macOS allows notifications for your terminal app.
4. Inside tmux, `allow-passthrough` is on.
5. New mail actually arrived in an INBOX. The first refresh after starting
   never alerts.

**Alerts while you're looking at the window.** Your terminal, or tmux, isn't
reporting focus. Turn on `focus-events` in tmux. Pressing any key tells
dk-email you're at the window.

**The title is empty after quitting.** dk-email clears the title on exit. Your
shell prompt or terminal sets it again.
